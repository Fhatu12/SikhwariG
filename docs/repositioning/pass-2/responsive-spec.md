# Responsive Spec

Prefer natural reflow over duplicated breakpoint-specific content.

| Area | Mobile | Tablet | Desktop |
| --- | --- | --- | --- |
| Hero | Single column; headline, copy, CTAs, facts | Text and facts can stack or use two columns | Two columns with fact panel |
| Credibility strip | One or two columns; compact facts | Two or three columns | Row/grid with all facts visible |
| Portfolio cards | Stacked | Two columns if space allows | Two columns |
| Four service cards | One column | Two columns | Two-by-two or four-card responsive grid |
| Selected Work | One card per row | Two columns with third wrapping | Three columns when content fits |
| Leadership | Stacked cards | Two columns if cards remain balanced | Two columns |
| Forms | One column; full-width controls | One/two columns only for short fields | Two-column field groups where useful |
| Navigation | Menu button and stacked menu | Desktop nav if width allows | Inline nav |
| Footer | Stacked legal/contact/service groups | Two-column grouping | Multi-column grouping with legal identity prominent |

## Text and Layout Rules

- Do not scale font size with viewport width.
- Keep card headings short enough to wrap cleanly.
- Avoid fixed heights for text-heavy cards.
- Use stable dimensions for badges and controls where possible.
- Maintain `Container` max width and existing section spacing.
